# 项目改进点子全集（持续更新）

> 原则：每条都标注【性价比】和【依赖】。标 ⭐ 的是我认为最能拉开差距的。

## 一、能让评审/用户眼前一亮的（差异化卖点）

### ⭐ 1. 消融对比：LLM vs LLM+情绪时间线
- 做法：同样 20 段对话，一组只给 LLM 原文，另一组附上我们的结构化情绪时间线+预警，人工盲评哪组建议更好。
- 价值：这是整个项目的核心论点——"时序感知让建议更准"。有了这个对比，项目从"套壳"变成"有论证的系统"。
- 【性价比：极高】【依赖：API Key + 20 段标注】

### ⭐ 2. 截图导入（OCR → 自动解析对话）
- 做法：用户直接粘贴微信/QQ 聊天截图，OCR 识别文字、按气泡左右侧自动区分说话人。
- 价值：真实用户不会手打聊天记录，截图是唯一自然的输入方式。参考 gravel-01/chat-agent 的链路。
- 【性价比：高】【依赖：OCR 库（macOS 可用 Vision 框架，或 paddleocr）】

### 3. 预警理由可解释化
- 做法：预警卡片不只显示"中风险"，而是高亮触发的具体轮次（"第 3–5 轮负面情绪连续上升"），点击可定位到原文。
- 价值：可解释性是这类系统的信任基础。
- 【性价比：高】【依赖：W4 预警 v1.0】

### 4. 同一对象的纵向档案
- 做法：用户可给对话打标签（如"和室友"），系统保存历史分析，展示"和这个人最近 5 次聊天的情绪走势"。
- 价值：从"单次分析工具"升级为"关系健康追踪"，是产品化的分水岭。
- 【性价比：中】【依赖：本地存储设计】

## 二、技术质量提升

### ⭐ 5. 概率校准（Temperature Scaling）
- 现状：TF-IDF+LR 的"置信度"没有校准，0.7 不代表 70% 可信。
- 做法：在验证集上拟合温度参数，让置信度接近真实正确率。
- 价值：预警和趋势都建立在概率上，概率不准则全盘皆输；校准只需几十行代码。
- 【性价比：极高】【依赖：无】

### 6. 上下文建模升级（换掉字符串拼接）
- 现状：W2 实验证明朴素拼接上下文反而掉点（0.39→0.21）。
- 做法：参考 TodKat（话题+说话人双编码）或 COSMIC（常识+说话人状态），或直接中文 RoBERTa 拼接 [SEP] 轮次+说话人标记重训。
- 【性价比：中】【依赖：W3 中文模型跑通后】

### 7. 中文对话域适配
- 现状：中文模型用微博单帖训练，和真实聊天对话有域差。
- 做法：接入 LLM 后，用 LLM 给 200–500 段真实/半真实中文对话打情绪标签，人工抽检后做二次微调（蒸馏路线）。
- 【性价比：高】【依赖：API Key】

### 8. 情绪熵纳入预警
- 现状：预警只看负面情绪；模型"拿不准"（高熵）本身是信号——激烈争吵中的文本往往让模型困惑。
- 做法：把平均熵/熵上升趋势作为第 5 个时序指标，W4 校准时一起网格搜索。
- 【性价比：高】【依赖：无，数据已存】

## 三、评估与可信度

### 9. 对话级评估指标
- 现状：只看单轮 Macro-F1。
- 做法：定义对话级指标——趋势方向判对率（人工标 20 段"这段在恶化/好转"对比系统输出）。
- 【性价比：高】【依赖：少量人工标注】

### 10. 建议质量反馈闭环
- 做法：每条回复草稿旁加"有用/没用"按钮，数据落盘，既是评估也是后续微调数据。
- 【性价比：中】【依赖：前端小改动】

### 11. 失败案例库
- 做法：把"讽刺误判""关键词陷阱"（如 not happy → happiness）整理成案例库，报告里单列一章。
- 价值：评审最看重对局限的诚实认知。
- 【性价比：高】【依赖：无】

## 四、工程与交付

### 12. 一键启动脚本
- 做法：`start.sh` 同时拉起后端（uvicorn）和前端（vite），检测端口占用。
- 【性价比：高】【依赖：无】

### 13. 隐私声明与数据流向图
- 现状：聊天记录是高度敏感数据，目前文档没提。
- 做法：README 和网站里写清楚——情绪分析全部本地跑，只有点了"生成建议"才发送给 LLM 服务商；附数据流向图。
- 价值：这既是伦理得分点，也是真实产品的必备项。
- 【性价比：高】【依赖：无】

### 14. Docker 打包（可选）
- 【性价比：低，课程项目不必】
