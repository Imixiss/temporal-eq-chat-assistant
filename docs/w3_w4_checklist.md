# 第 3–4 周可执行 checklist（W3–W4）

> 前置状态：W1–W2 已交付英文 ERC 基线（Macro-F1 0.3921）、趋势图、时序指标函数、预警启发式占位、网站框架（LLM 接口已预留）。
> W3–W4 的两个核心目标：**① 让系统能分析中文对话（M3）；② 把冲突预警从"拍脑袋阈值"变成"有数据支撑的规则"（M4）。**

## 第 3 周：中文情绪识别能力（目标：M3 中文可分析）

| # | 时间 | 具体动作 | 产出物 | 验收标准 |
|---|---|---|---|---|
| 3.1 | W3-D1 | 安装 transformers/torch（已存在 torch 2.14）；从 hf-mirror 下载 `hfl/chinese-roberta-wwm-ext`（约 400MB） | 模型落盘 | `python -c "from transformers import AutoModel; ..."` 无报错 |
| 3.2 | W3-D1–D2 | 选定中文情绪数据集：优先微博情绪分类数据（NLPCC2013/2014 或 HF 上可用的 weibo 情绪集），字段统一为 `{text, label}`；标签映射到项目 7 类体系（没有的类标注"不支持"） | `src/data/prepare_zh.py` + 数据落盘 | 脚本一键跑完；打印 5 条样本人工确认标签合理 |
| 3.3 | W3-D2–D3 | 微调中文 ERC 模型：单轮文本分类，先不加上下文；固定种子；保存混淆矩阵 | `src/models/train_erc_zh.py` + checkpoint | 3 个 epoch loss 下降；测试集 Macro-F1 有具体数字；与微博情绪任务的公开基线（约 0.6–0.7 量级）对比，差距过大要查数据问题 |
| 3.4 | W3-D4 | 把中文模型接入分析服务：`server/app.py` 按输入语言自动路由（检测中文 → 中文模型，英文 → 现有模型） | 后端双语路由 | 网站粘贴中文聊天记录，能返回每轮情绪+概率，且抽查 5 条预测语义合理 |
| 3.5 | W3-D4 | ESConv 数据接入：解析对话级情绪类别 + 支持者策略标注，统一进 JSONL（`strategy` 字段）——**不做逐轮情绪监督，只用于 W5+ 的生成层** | `src/data/prepare_esconv.py` | 能打印 3 段完整 ESConv 对话；策略标签枚举表写入 `docs/dataset.md` |
| 3.6 | W3-D5 | **周中检查 + 趋势图升级**：趋势图按说话人分两条线（避免混合双方情绪造成误导）；补 EmpatheticDialogues 跨数据集检验（可选，时间紧就砍） | 升级版趋势图 ×12 | 同一段对话能看出"谁在恶化"；文档更新 |

**W3 里程碑（M3）**：网站粘贴中文记录 → 逐轮中文情绪 + 分说话人趋势图，全部真实可跑。

⚠️ 风险预案：若微博数据下载/解析卡住超过 1 天，降级方案 = 用 LLM 零样本打情绪标签（需 API Key）或先用机器翻译把中文翻成英文走现有模型（质量差，仅保底，结果须标注"翻译路线"）。

## 第 4 周：预警校准 + 建议层联调（目标：M4 预警有依据、端到端可用）

| # | 时间 | 具体动作 | 产出物 | 验收标准 |
|---|---|---|---|---|
| 4.1 | W4-D1 | 用 W3 的模型在中文数据上跑出 ≥200 段对话的情绪序列，观察四个时序指标的分布（直方图、分位数） | `outputs/metrics/zh_temporal_distribution.json` + 分布图 | 能说出"斜率的 P90 是多少"这类具体数字 |
| 4.2 | W4-D1–D2 | **人工标注**：从上述对话抽 50 段，人工判断"是否存在冲突升级"（是/否/不确定），两人标注或一人两遍，记录分歧 | `data/annotations/conflict_labels.csv` | 50 段标完；标注规范写了 5 条以上（什么算冲突升级） |
| 4.3 | W4-D2–D3 | 基于分布 + 标注校准预警阈值：网格搜索阈值组合，选 F1 最优；报告 precision/recall，样本量小要加置信区间说明 | `src/analysis/calibrate_warning.py` + `docs/warning_calibration.md` | 预警规则从 v0.1 升级到 v1.0；**报告里写明"基于 50 段自标注数据，非公开基准"** |
| 4.4 | W4-D3–D4 | LLM 建议层联调：拿到 API Key 后跑通 Kimi/DeepSeek；调 prompt（把情绪时间线、预警等级、reason_codes 结构化进 prompt）；对 20 段对话人工评分建议质量（相关性/可操作性/语气，1–5 分） | `docs/llm_eval.md` | 20 段平均分有数字；至少迭代过 2 版 prompt 并记录差异 |
| 4.5 | W4-D4 | 网站打磨：预警理由可视化（哪几轮触发了预警要高亮）、建议区 loading 态、错误提示 | 前端更新 | 走一遍完整用户路径无死路 |
| 4.6 | W4-D5 | **中期评审**：整理 W1–W4 全部产出，写中期报告（问题→方法→数据→结果→局限），准备 5 分钟演示 | `docs/midterm_report.md` | 能现场演示：粘贴中文对话 → 趋势图 → 预警 → 建议+回复草稿 |

**W4 里程碑（M4）**：中文端到端可用 + 预警规则 v1.0（有校准依据）+ LLM 建议层跑通 + 中期报告。

## 两条红线（继承 W1–W2 原则）

1. **预警规则的每次改动都要有校准记录**，不许凭感觉调阈值后直接宣称"准确率提升"；样本量只有 50 段，报告里必须写清局限。
2. **LLM 建议质量不能只靠"看着不错"**，必须有评分表（哪怕只有 20 段人工评分），否则中期报告里只能说"实现了功能"，不能说"效果良好"。

## 时间不够时的砍单顺序

先砍 3.6 的 EmpatheticDialogues → 再砍 4.5 的前端打磨 → 保住 3.3/3.4（中文模型）和 4.2/4.3（标注与校准），这两个是项目的立身之本。
